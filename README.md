# 白色失明文字麻将

> 汉字组词造句 · 人机混战 · WebRTC 联机 · 单文件 HTML 游戏

一款基于汉字组词玩法的文字麻将游戏。手牌由汉字组成，通过吃牌、组词造句来胡牌。支持 **2-6 人** 真人联机和人机混战，单文件即可运行。

## ✨ 功能特性

- **🀄 汉字麻将**：基础 144 张 + 扩充 48 张（6 个主题包，可自由勾选启用），**每字恰好 1 张**，词库 676 条
- **👥 2-6 人**：支持 2 至 6 人对局，方位按人数自动环形排布，不足人数由 AI 补齐
- **🎲 掷骰定庄**：每人掷 1 枚骰子，点数最大者坐庄；出现平局则全员重投
- **🎯 三档判定机制**：入门（本人认可）/ 进阶（50% 认可）/ 严格（全员认可），开局前由房主选择
- **⏳ 听牌系统**：13 张差 1 字即可听牌，支持自摸与他人点炮，界面显示「✦听」标识
- **🤖 人机混战**：AI 纯随机出牌，摸到能胡的牌自动申请
- **🌐 双模式联机**：默认走声网 RTM 中继通道；也支持自建 WebSocket 信令服务器 + WebRTC P2P
- **🔐 前端零密钥**：联机通行证由 Cloudflare Pages Function 签发，AppCertificate 只存在服务端
- **📱 手机适配**：大厅竖屏 + 对局横屏自动切换，自动全屏并锁定横屏，竖屏进入弹出旋转提示
- **🔄 掉线重连**：刷新页面自动恢复对局，房主退出自动迁移（座位号最小的真人接管）
- **🔗 分享链接**：一键复制房间信息，房客打开自动识别并填入信令地址 + 房间号
- **🖱️ 手牌拖拽**：自由整理手牌顺序（仅影响显示）
- **💬 房间聊天**：内置聊天面板，默认收起可展开
- **📖 规则弹窗**：大厅和对局内均可随时查看玩法规则

## 🎮 游戏规则

### 基本流程
1. **掷骰定庄**：开局前每人掷 1 枚骰子，点数最大者坐庄（平局则全员重投），由庄家先手
2. 每名玩家起手 13 张牌
3. 摸牌 → 出牌 → 下家选择吃/胡/过
4. 吃牌后跳过摸牌，直接出牌
5. 直到有人胡牌或牌库摸空（流局）

### 人数与牌库
- **支持 2-6 人**，方位按人数自动环形排布（自己固定在下方位）
- 大厅可选择目标人数（2/3/4/5/6），不足部分由 AI 补齐
- **牌库可配置**：基础 144 张默认启用，6 个扩充主题包（意境/玄学/人类/黑暗/抽象/猛兽）可自由勾选，鼠标悬停可预览该包 8 个字

### 吃牌
- 只能吃**上家**打出的牌，用手牌 + 打出的字组成词库中的词语
- 吃牌后跳过摸牌，直接出牌
- **官方式吃牌**：吃牌时无需亮出词组，对手只能看到吃了哪张牌
- **无碰牌**：牌库中每个字只有 1 张，无法凑齐 3 张

### 听牌
- 手中 13 张只差 1 个字就能胡时进入**听牌**状态
- 听牌后可通过「**自摸**」（自己摸到）或「**点炮**」（用他人打出的牌）来胡
- 界面会在名字后显示「✦听」标识，状态栏显示「已听牌」

### 胡牌与判定机制
- **判定机制由房主开局前选择，共三档**：
  - **入门**：玩家本人认可即算胡牌
  - **进阶**（默认）：50% 以上玩家认可即算胡牌
  - **严格**：所有玩家认可才能胡牌
- 胡牌文本可以是一整句通顺的句子，也可以自由断句，允许谐音
- **AI 胡牌**：系统自动校验 14 张能否全部拆分成词库中的词语或短句
- AI 不参与投票，仅真人之间互相投票

### 人机混战
- 按房主选择的目标人数补齐 AI（最少 2 人开局）
- AI 纯随机出牌，摸到能胡的牌自动申请胡牌
- AI 有 30% 概率吃牌
- AI 胡牌也需按所选判定机制裁决（AI 之间不互相投票）

## 🌐 联机部署

支持两种联机方式，玩家可根据情况选择：

### 方式一：声网 RTM 公共通道（默认，推荐）

**信令服务器地址留空**即使用声网 RTM 公共中继通道。游戏数据通过声网全球节点中继广播，不受 NAT 打洞限制，手机跨网络（4G/5G/WiFi）也能稳定联机。

> 说明：联机通行证（token）由 Cloudflare Pages Function（`functions/api/token.js`）签发，需在 Cloudflare 配置 `AGORA_APP_ID` / `AGORA_APP_CERT` 环境变量。 **本公开仓库不含任何密钥，直接部署将无法联机。**
>
> 声网 RTM 免费额度为每月 100 万条消息，个人娱乐完全够用。

### 方式二：自建信令服务器（可选）

在「信令服务器地址」框填入自建服务器地址（房主需先启动服务器并用 ngrok 暴露公网），游戏数据走浏览器间 WebRTC P2P 直连。适合对隐私有更高要求或想完全自主掌控的场景。

项目提供 Python 和 Node.js 两个版本：

```bash
# Python 版（纯标准库实现，无需安装依赖）
python signaling-server.py

# Node.js 版
npm install ws
node signaling-server.js
```

默认监听 `ws://0.0.0.0:8765`，用 ngrok 映射到公网：

```bash
ngrok http 8765
```

将 ngrok 给出的 `https://xxx.ngrok-free.app` 改成 `wss://xxx.ngrok-free.app`，填入游戏大厅的「信令服务器地址」框，所有玩家填同一个地址即可联机。

> 注意：WebRTC P2P 在部分运营商网络（如移动 4G）下可能打洞失败，导致无法联机。如遇此问题请切换到方式一声网公共通道。

### 分享链接

- 房主点击「分享链接」即可复制包含信令地址 + 房间号的文本
- 房客打开游戏网址后会自动读取剪贴板，识别并填入信令地址 + 房间号

### GitHub Pages 部署

1. 将本仓库上传到 GitHub
2. Settings → Pages → Source 选 `Deploy from a branch`，Branch 选 `main` / `(root)`
3. 等待 1-2 分钟即可获得访问地址

## 🛠️ 技术栈

- **前端**：纯 HTML + CSS + 原生 JavaScript，无框架
- **公共联机**：声网 Agora RTM（中继广播，跨网络稳定），token 由 Cloudflare Pages Function 签发
- **自建联机**：WebRTC (RTCPeerConnection) + WebSocket 信令
- **构建**：无构建工具，单文件直接运行
- **存储**：localStorage 保存对局状态用于重连

## 📝 注意事项

- 默认使用声网 RTM 公共通道联机，需要配套的 Cloudflare Pages Function 提供联机通行证（token），本仓库不含任何密钥
- 自建信令模式下，部分运营商网络（如移动 4G）可能 WebRTC 打洞失败，建议切换声网公共通道
- STUN 保留 3 个（2 个 Google + 1 个第三方），用于自建信令模式下的 NAT 穿透
- iOS Safari 对横屏锁定 API 支持有限，可能需手动旋转手机
- 部分公司/学校网络会屏蔽 WebRTC，可切换手机热点测试
- 对局状态保存在 localStorage（key 为 `mahjong_save_房间号`），重进同房间可恢复
- 牌库和词库可在 `index.html` 的 `CARD_CHARS` 和 `HU_WORDS` 变量中自定义
